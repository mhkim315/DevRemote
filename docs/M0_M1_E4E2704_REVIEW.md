## BLOCKER 1 — HTTP command policy does not prove locality

`createFromProfile()` permits arbitrary custom argv whenever
`Handlers.InsecureLocalOnly` is true. That flag controls daemon development
configuration; it does not authenticate the origin of an individual request.

The accepted real-device setup uses:

```text
Cloudflare tunnel
→ 127.0.0.1:9171
→ daemon --insecure-local-only
```

The tunnel makes a remote request arrive through the localhost listener. It can
therefore reach the same custom-command branch. Request IP/loopback checks would
not solve this boundary.

There is also a direct bypass: omit `profileId`, use the legacy HTTP payload,
and provide a command string. That path still executes through `bash -c`.
Consequently, the test "custom denied for remote" does not prove the public
session-create boundary is safe.

Required correction:

- HTTP profile creation may expose only daemon-approved presets for this MVP;
- arbitrary/custom launch must use a separately authenticated privileged local
  channel, preferably the existing `0600` Unix socket, or an equivalently strong
  local capability not forwarded through the tunnel;
- the legacy `pokit run` command path must be moved/protected so a remote HTTP
  caller cannot select it merely by changing JSON shape;
- do not use `InsecureLocalOnly` or `RemoteAddr` as proof that the caller is a
  local CLI process;
- add a production-boundary test proving both custom-profile and legacy-shape
  HTTP requests cannot bypass the policy.

Preserving CLI behavior is required, but preserving an unsafe transport is not.

## BLOCKER 2 — create reports running when Recorder startup fails

`startRecorderForSession()` returns no result and silently ignores:

- session lookup failure;
- missing `StreamOpener`;
- `EnsureRecorder()` / `OpenStream()` failure.

`createFromProfile()` then unconditionally returns `LifecycleRunning`.

This violates the M1 contract:

```text
runtime created
→ Recorder ready
→ API exposes running
```

Required correction:

- make Recorder readiness explicit and return an error/result;
- never return `running` unless the single Recorder is alive and ready;
- on readiness failure, converge on a defined startup-failure cleanup path so
  an unrecorded process is not left running;
- return a structured failed/non-success response;
- add a production-path test whose session exists but `OpenStream()` fails and
  assert that `running` is never returned and cleanup occurs.

Do not solve this by allowing the HTTP handler or mobile client to open/read the
PTY. Recorder ownership remains unchanged.

## BLOCKER 3 — malformed legacy command silently changes behavior

The legacy path ignores `json.Unmarshal(req.Command, &cmdStr)` errors. A command
with the wrong JSON type becomes an empty string; controlled PTY creation can
then fall back to the default shell.

Required correction:

- reject missing, non-string, or malformed legacy command data;
- do not turn an invalid create request into a different valid session;
- add API tests for object/number/null/missing legacy command forms.

## FOLLOW-UP — starter subscriber ownership

`EnsureRecorder()` returns an initial subscriber channel. The create path
discards that channel without unsubscribing, leaving a bounded phantom
subscriber until Recorder shutdown.

Correct this while making Recorder readiness explicit, but do not redesign the
Recorder solely for testability. A start-without-viewer operation should not
create a retained viewer subscription.
